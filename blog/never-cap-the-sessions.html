Never cap the sessions

Nov 17, 2026

People see this screenshot and ask how I keep track of it all. Honest answer: I don't track the windows. I track the board.

I am one person. I don't write most of the code anymore. I decide what gets built, I correct course, I approve what ships. The sessions do the rest — in parallel, all the time. In the last 30 days my coding agent alone ran 2,181 sessions. Not 2,181 prompts. Sessions.

“Running that many AIs must be hard”

It is. I said exactly that today, looking at this screen. Every session eventually comes back with a question, a decision, a “your turn.” A dozen sessions means a dozen queues, all of them pointing at one human.

But here is the thing nobody gets: the hard part is not the number of sessions. The hard part would be shipping all of this with three.

Active sessions are never capped. That is the source of my productivity.

A cap sounds like discipline. It is not. A cap is a queue of work that hasn't started, ideas going stale while they wait for a slot. My bottleneck was never ideas, and it was never code. It was one pair of hands. The sessions removed the hands from the equation. Capping them puts the hands back.

The board is the single pane

What makes unlimited parallel manageable is not a bigger screen. It is a contract. Every session I spawn works in its own worktree and ends with exactly one of two lines:

AGENT-BOARD: DONE — what shipped, and how it was verified.
AGENT-BOARD: BLOCKED — what is missing, and what it needs from me.

The agent board collects those reports into one pane. I read reports, not terminals. The wall of windows sits behind the board, and I almost never look at it directly — except on evenings like this one, when I screenshot it because, honestly, it looks iconic.

The machine pays for it. Good.

None of this is free, and the Activity Monitor does not lie about it:

People look at numbers like that and suggest closing some sessions to “give the machine a break.” That is solving the wrong problem. RAM is a hardware problem — the fix is more RAM. Quota is a plan problem — the fix is a bigger plan. Sessions are the product. You do not fix a factory by switching off machines.

The rule going forward

So the wall stays. It will probably get bigger. One architect, one board, as many sessions as the work needs.

Cap the meetings. Cap the context switches. Never cap the sessions.
